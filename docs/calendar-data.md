# 离线历法与节假日数据

## 农历和节气

- 生成工具：[`lunar-python` v1.4.8](https://github.com/6tail/lunar-python/tree/v1.4.8)，MIT，Copyright (c) 2020 6tail。
- 许可证随 APK 保留在 `app/src/main/assets/calendar/LICENSE-lunar-python.txt`。
- `tools/generate-almanac.py` 为构建前的离线数据生成工具；应用不引入 Python 或该库的运行时代码，不需要网络。
- `months.csv`：每行依次为相对 1900-01-01 的日偏移、农历年、有符号月份（负值为闰月）、月长度。含边界缓冲月；UI 只允许公历 1900-01-01 至 2100-12-31。
- `terms.csv`：公历日期、节气编号。编号按小寒、大寒、立春等顺序，一年 24 个，共 4824 个。使用中国历法日期（UTC+8）；不按设备时区重新计算天文瞬间，跨时区仍显示该公历日的中国农历/节气。
- 公历日期在设备本地按日取值，数据库记录是日期字符串；已有事项不会因设备时区变动平移。
- 边界之外的相邻月日期不显示农历，不允许选择。
- 校验参考：[香港天文台 2026 年公农历对照表](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2026e.txt)、[2024 年对照表](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2024e.txt)。自动测试覆盖 2026 年 24 节气及主要节日，逐日验证支持范围内农历连续性，并检查 2033 年闰十一月。
- 古远年份与接近午夜的天文边界以生成库计算为准，不把全范围结构校验等同于全部日期的独立天文精度认证。

再生成（开发工具放外置盘，不在应用内执行）：

```sh
python3 -m venv ../.tools/ink-calendar/calendar-tools
../.tools/ink-calendar/calendar-tools/bin/pip install lunar_python==1.4.8
../.tools/ink-calendar/calendar-tools/bin/python tools/generate-almanac.py
```

## 节日名称与年度放假安排

- 地区固定为中国大陆；切换中文/英文只翻译名称，不切换国家。
- 名称覆盖元旦、春节、除夕、元宵、清明、劳动节、端午、中秋、重阳、国庆。节日名称不代表当天一定放假。
- 年度放假/补班目前只内置 2026 年，由 `Holidays.java` 中的明确日期表提供。
- 来源：[国务院办公厅关于2026年部分节假日安排的通知（国办发明电〔2025〕7号，北京市政府转载）](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)。已核对共 33 个公布的休假日期和 6 个补班日期；普通周末不额外加“休”标记。
- 其他年份显示“本年调休数据未收录”，只提供可计算的节日名称。不根据周末或前一年安排猜测补班，也不提供薪资、法定计薪日等劳动法判断。
- 开关关闭时同时隐藏节日名称和休/班标记；“清明”仍可作为独立开启的节气显示。
- 年度安排随后续应用版本更新；本版不自动联网更新。

## 纪念日规则

- 普通事项仍是一次性记录。纪念日是独立类型，不生成重复事项，也不触发通知。
- 纪念日保留原始公历日期；中文界面可选择按其对应农历月日纪念。英文界面继续计算已有农历纪念日，并允许查看/修改其选项，不显示农历日期或节气。
- 原日期在未来时，直接倒数至原日期；过去的纪念日寻找今天或之后的下一次周年。
- 2 月 29 日逢平年按 2 月 28 日；闰月在没有同名闰月的年份按同名常月；三十遇小月按廿九。存在同名闰月的年份只取该闰月，不同时计算常月。
- 下一次周年超过 2100 年时明确显示超出支持范围，不溢出或隐式改年。
- 天数以日期差计算，起始日计 0 天，避开夏令时导致 23/25 小时一天的问题。
- 倒计时到期后保留原目标日并显示已过天数，不自动推进下一年。
